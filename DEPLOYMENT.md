# GST Bharat Deployment

Target setup:

- Backend API on Render
- PostgreSQL on Render
- Persistent Render disk for uploads and generated exports
- Frontend on Vercel

## 1. Deploy Backend On Render

Use `render.yaml` from the repository root as a Render Blueprint.

Render will create:

- `gst-bharat-api`
- `gst-bharat-db`
- `/var/data` persistent disk for uploads and exports

Set these backend environment variables in Render:

```bash
CORS_ORIGINS=https://your-vercel-app.vercel.app
ADMIN_EMAIL=admin@example.com
ADMIN_PASSWORD=strong-admin-password
RAZORPAY_KEY_ID=
RAZORPAY_KEY_SECRET=
RAZORPAY_WEBHOOK_SECRET=
```

Keep `SECRET_KEY` generated by Render or set a long random value. Do not use the local development value.

After deploy, verify:

```bash
https://your-render-api.onrender.com/health
https://your-render-api.onrender.com/health/readiness
https://your-render-api.onrender.com/marketplaces
```

## 2. Deploy Frontend On Vercel

Create a Vercel project with:

```bash
Root Directory: apps/web
Framework Preset: Next.js
Build Command: npm run build
Output Directory: .next
Install Command: npm ci
```

Set this Vercel environment variable:

```bash
NEXT_PUBLIC_API_BASE=https://your-render-api.onrender.com
```

Redeploy after setting the variable.

## 3. Connect CORS

After Vercel gives the final domain, update Render:

```bash
CORS_ORIGINS=https://your-vercel-app.vercel.app,https://your-custom-domain.com
```

Use exact origins only. Do not include trailing slashes.

## 4. Production Notes

- Use Render PostgreSQL, not SQLite, for production.
- Keep `UPLOAD_DIR=/var/data/uploads` and `EXPORT_DIR=/var/data/exports` on Render so generated files survive restarts.
- If you add a custom frontend domain, add that domain to `CORS_ORIGINS`.
- If Razorpay is enabled, configure its webhook URL as:

```bash
https://your-render-api.onrender.com/billing/webhook
```

## 5. Local Checks Before Deploy

Backend:

```bash
cd apps/api
./.venv/bin/python -m pytest -q
```

Frontend:

```bash
cd apps/web
npm run lint
npm run build
```
